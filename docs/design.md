# 设计说明：为什么结果是确定、可解释、可复现的

## 确定性

- **并发串行化**：引擎所有提交/关轮路径持同一把锁；提交先持久化再改内存，
  崩溃点只会落在“事件已落盘”或“完全未发生”两者之一。
- **顺序无关聚合**：加权中位先对（价格, 来源ID）稳定排序；权重累计过半取第一档，
  相同输入无论到达顺序如何，结果一致。
- **轮次单调**：`round_id` 恒为上一轮 +1；open 状态禁止再开轮；
  发给非当前轮的提交一律 `closed_round`，杜绝跳轮与串轮。

## 可解释性

- 拒绝提交返回机器可读原因（`malformed/unauthorized/expired/future_quote/
  duplicate/closed_round`）与人类可读 detail。
- 关轮结论附带 `CheckTrace` 列表：陈旧计数、min_sources 实测/阈值、
  加权中位原值、硬带是否钳制、偏差实测/阈值，全部随终局事件持久化。
- `fallback` 结果通过 `derived_from_round` 指明价格来自哪一轮及原因。

## 可复现性

- 终局事件保存：轮次配置版本、关轮时刻、全部已接受提交（含签名信封）、
  规则检查轨迹。重放 = 用同一版本配置重新跑纯函数聚合器。
- 配置历史按版本号保存；`verify` 在正确的轮次边界登记升级，
  因此“升级前进行中的轮次冻结旧规则”也能精确复刻。
- 硬价格带与偏差策略区分“报价行为”和“产出结果”：串通可被钳制或拒绝，
  但原始中位值保留在 `median_raw` 中，审计时仍可见来源实际做了什么。

## 简化与边界（本地模拟）

- HMAC 共享密钥模拟链下签名，不涉及真实密钥管理与链上验签。
- 时间由调用方传入纳秒时间戳，测试中完全可控；生产接入时替换为单调时钟即可。
- 事件日志为单机 JSONL；多副本一致性不在本组件范围内。
